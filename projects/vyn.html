One autonomous system.

Research and constraints

The product is shaped by three kinds of constraint.

User constraints

Time scarcity between classes.

Trust barriers with unknown couriers.

Location ambiguity.

Receiver availability that cannot be assumed.

System constraints

Robot utilization and battery.

Operating zones.

Route variability.

Network reliability behind a simple ETA.

Organizational constraints

Department hours.

Institutional accountability.

Verified identities.

Who can send, receive, and intervene.

Conceptual product exploration informed by campus logistics, robotics operating patterns, and delivery failure modes. Not presented as a completed field study.

02

VYN Command

From monitoring robots to commanding outcomes.

This is a robot monitoring, fleet operations, mission management, and exception management product. Not an analytics dashboard. Within about five seconds the operator should know whether anything is wrong, which robot, where, why, and whether they need to act.

Components that prove the system

Primary / secondary / danger buttons. Robot row. Mission row. Attention item. Incident card. AI recommendation. Status badge. Search, filters, tabs, stepper. Map markers for robot, route, incident, charger, restricted zone. 8px spacing. 44px touch on tablet. Consequential actions confirm. Emergency actions stay distinct.

Accessibility: WCAG AA contrast, keyboard access, visible focus, reduced motion, semantic HTML, no color-only states. Direct teleoperation is opt-in, not ambient.

Reflection

Designing VYN changed the problem from “How should a robot-delivery app work?”

to “How should humans interact with an autonomous system when they have completely different responsibilities?”

User

Trust autonomy without managing it.

Operator

Understand autonomy without constantly controlling it.

AI

Reduce attention without removing authority.

System

Design failures as deliberately as success.
